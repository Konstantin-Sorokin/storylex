# Техническое задание: приложение для изучения английского по произведениям

**Версия:** 1.0 (рабочая спецификация для архитектурного проектирования)  
**Дата фиксации:** 10 ноября 2026 г.  
**Язык документа:** русский  
**Цель передачи:** предоставить ИИ-агенту и разработчику единый источник продуктовых требований.  
**Статус:** подтверждённые продуктовые решения сведены вместе; неутверждённые технические механизмы помечены отдельно.

> **Правило интерпретации.** Более поздние решения имеют приоритет над ранними. В частности, актуальная модель — гибридная: обычные уроки и изменения личного словаря доступны офлайн с последующей отправкой, интервальные повторения — только онлайн. Авторизация обязательна при первом запуске; облако хранит прогресс. Если документ не задаёт технический алгоритм, агент должен сначала предложить решение и получить согласование, а не считать его утверждённым.

## 1. Назначение и границы продукта

Мобильное приложение помогает подготовиться к **чтению конкретных книг** и **просмотру конкретных фильмов или сериалов на английском**. Оно обучает словам, устойчивым выражениям, фразовым глаголам и полезным грамматическим конструкциям, встречающимся в соответствующем произведении. Это не читалка, видеоплеер и не общий курс английской грамматики.

- Первый релиз: **Android**, публикация первоначально в **RuStore**. iOS — позднее.
- Первоначальный основной рынок — Россия; интерфейс поддерживает русский и английский.
- Разработчик — один человек; приоритеты: простота поддержки, проверяемость, возможность начать личное использование раньше коммерческого запуска.
- Новые функции, не описанные ниже, не добавлять по инициативе агента. Не строить «универсальную платформу» на будущее ценой сложности MVP.

### 1.1. Основной пользовательский путь

1. На первом запуске пользователь входит через поддерживаемого внешнего провайдера.
2. Приложение подготавливает локальный каталог, обложки и доступные бесплатные пробные материалы.
3. Пользователь выбирает книгу, сезон сериала или фильм в каталоге.
4. Он изучает пробную часть (если она назначена) либо приобретает материал / добавляет полностью бесплатный материал в библиотеку.
5. Открывает главы, эпизоды и уроки по порядку; стандартный урок — пять учебных единиц.
6. По желанию сохраняет отдельные слова в личный словарь.
7. При наличии интернета проходит интервальные повторения сохранённых слов.
8. На другом устройстве получает права доступа и синхронизированный прогресс из аккаунта.

## 2. Стек и ответственность компонентов

### 2.1. Клиент

- React Native, Expo, TypeScript.
- SQLite — локальный каталог и метаданные, скачанные учебные материалы, кэш обложек/ресурсов, локальный прогресс обычных уроков и очередь несинхронизированных операций.
- Смартфон, вертикальная ориентация. На планшете допустим телефоноподобный интерфейс; отдельную планшетную компоновку не разрабатывать.
- Динамическое увеличение системного размера текста; интерфейс не должен обрезать предложения и варианты ответов.

### 2.2. Сервер

- Python, Django, Django REST Framework, PostgreSQL.
- Django Admin — единственная обязательная CMS для автора на старте.
- Сервер — источник истины для аккаунтов, прав доступа, покупок, подтверждённого прогресса, личного словаря и состояния интервальных повторений.
- Сервис развёртывается там, где доступен из приложения. Локально запущенного Django недостаточно для публичной авторизации, синхронизации и покупок.

### 2.3. Распространение контента

- Версионированные JSON-пакеты и изображения могут распространяться через Yandex Object Storage или сопоставимое объектное хранилище.
- Каталог и общедоступные пробные материалы допускают статическую доставку; **платные пакеты нельзя открыто публиковать по постоянным общедоступным URL**.
- Перед выдачей платного пакета сервер проверяет entitlement (право доступа). Точный механизм доставки (краткоживущий подписанный URL, прокси через API или другой) утвердить при проектировании.
- Клиент хранит скачанные материалы, чтобы не получать их повторно на каждом экране. Полную невозможность извлечь содержимое из устройства не обещать.

## 3. Предметная модель произведений

| Тип | Иерархия | Приобретаемая единица | Порядок обучения |
|---|---|---|---|
| Книга | Книжная серия (необязательно) → книга → глава → урок | Отдельная книга | Главы и уроки последовательно внутри книги |
| Сериал | Сериал → сезон → эпизод → урок | Отдельный сезон | Эпизоды и уроки последовательно внутри сезона |
| Фильм | Фильм → урок | Фильм целиком | Уроки последовательно |

- Книги одной серии и сезоны сериала покупаются **независимо**, в любом порядке.
- В общем каталоге **одна карточка на книжную серию** и **одна на сериал**, внутри — только опубликованные книги/сезоны. Отдельные книги и сезоны должны находиться глобальным поиском.
- Книжная серия использует на общей карточке обложку первой **опубликованной** книги; сериал — первого опубликованного сезона.
- Книга без серии и фильм отображаются отдельными объектами.
- Для книги/сезона/фильма доступен независимый статус публикации и цена.
- Произведение публикуется только когда все предусмотренные для конкретной продаваемой единицы главы/эпизоды/уроки подготовлены. Не нужно ждать готовности всех будущих книг серии или сезонов сериала.

### 3.1. Метаданные

- Название и описание для русского и английского языков интерфейса.
- Год публикации (книги) либо выхода (фильмы, сериалы). **Точное расположение года на экранах уточняется при дизайне.**
- Автор книги; для фильмов и сериалов режиссёр/создатель не требуется.
- Приблизительный уровень сложности английского — категория или диапазон CEFR на уровне продаваемого произведения, **не на уровне отдельных слов**.
- Общее количество слов/выражений и уроков; количество глав/эпизодов, где применимо.
- Цена, режим доступности (платный/полностью бесплатный), наличие пробной части.
- Жанры, хронометраж фильмов, расширенные данные актёров/создателей в MVP не нужны.

## 4. Обложки и изображения

- Все обложки: **вертикальный формат 2:3**.
- Создаются вручную, в том числе с помощью ИИ, проверяются автором и загружаются через Django Admin.
- Одна версия обложки для обоих языков интерфейса; надпись — оригинальное английское название. Локализованное название отображать отдельным текстом интерфейса.
- Для книг одной серии и сезонов одного сериала предпочтительны **собственные разные обложки в общем стиле**. Это дизайнерское предпочтение, а не необходимость создавать обложку каждому материалу автоматически.
- Публикация технически возможна без загруженной обложки: приложение показывает типографическую заглушку с названием. На практике автор намерен выпускать материалы с полноценными обложками.
- Не копировать защищённые официальные обложки, постеры, визуальные образы персонажей или фирменное оформление без соответствующих прав.

## 5. Авторизация и аккаунты

- **Авторизация при первом запуске обязательна**. Раннее решение о входе только при первой покупке отменено.
- Для первой Android-версии поддерживаются **Google** и **Яндекс ID**.
- Архитектура позволяет подключить **VK ID**, позднее Apple и связать несколько провайдеров с одним аккаунтом.
- Привязка провайдера только при подтверждённом владении; **не объединять аккаунты автоматически лишь по одинаковому email**.
- Собственные пароли, авторизация по email-коду в первой версии не нужны.
- Профиль минимальный: связанные провайдеры и email, если он предоставлен. Аватар и редактирование имени не нужны.
- После успешного входа обычные скачанные уроки доступны офлайн даже при истечении срока текущего токена; обновление сеанса и отправка накопленного прогресса — после восстановления подключения.
- При выходе из аккаунта скачанные файлы остаются на устройстве, но доступ к персональным данным и платным пакетам ограничивается текущим владельцем. Локальные данные разных аккаунтов изолированы.
- Пользователь может удалить аккаунт из настроек с отдельным подтверждением и предупреждением о потере данных/возможных последствиях для покупок; юридические и платформенные правила для удаления платежных записей проверить отдельно.

## 6. Первый запуск, подготовка локальных материалов

После успешной первоначальной авторизации приложение загружает и сохраняет:

1. Общий каталог произведений.
2. Все обложки каталога в оптимизированном формате.
3. Бесплатные пробные JSON-пакеты **только для тех произведений, где пробная часть включена автором**.
4. Список прав доступа и метаданные приобретённых/полученных бесплатно произведений; соответствующие полные пакеты при необходимости скачиваются автоматически.

- Для первого наполнения показывать понятный экран/индикатор подготовки. Не нужен многостраничный onboarding.
- После подготовки пользователь открывает приложение в разделе **«Моя библиотека»**.
- Приложение должно корректно обрабатывать сбой сети и повторить неполную загрузку без повреждения уже сохранённых данных.
- Не требовать кнопки ручной загрузки для каждого приобретённого произведения. Пакет начинает скачиваться автоматически после выдачи права доступа; при сетевой ошибке — автоматически повторяет попытку. Если скачивание не завершено, на карточке материала допустим небольшой индикатор проблемы с пояснением по нажатию.
- В первой версии не требуется UI удаления скачанных произведений.

## 7. Навигация приложения

Четыре основных раздела нижней навигации:

1. **Моя библиотека** — стартовый.
2. **Каталог**.
3. **Повторения**.
4. **Настройки**.

Без отдельной главной страницы.

### 7.1. «Моя библиотека»

Верхние вкладки:

- **«Изучаю»**: только материалы, по которым завершён хотя бы один обычный урок и которые ещё не полностью пройдены. Сортировка — по последнему завершённому учебному действию.
- **«Мои материалы»**: все приобретённые и бесплатно добавленные книги/сезоны/фильмы, включая завершённые и ещё не начатые.

«Мои материалы» группируются по книгам, сериалам и фильмам; порядок групп задаёт пользователь. Внутри книжной серии и сериала — вертикальные списки томов/сезонов. У родителей нет собственного суммарного прогресс-бара.

- Если обучение ещё не начиналось, прогресс на карточке не показывать.
- У начатой книги показывать **число полностью завершённых глав**, у сезона — **эпизодов**, у фильма — **уроков**; строка вида «X из Y ...» + прогресс-бар.
- Полностью пройденное произведение показывать как «Пройдено» с заполненным прогрессом.
- Завершённое произведение остаётся в «Моих материалах», но исчезает из «Изучаю».
- При публикации новых уроков ранее завершённое произведение снова становится неполным и возвращается в «Изучаю» после синхронизации.
- Предусмотреть понятные пустые состояния и переходы в каталог/«Мои материалы».

### 7.2. Каталог

- Верхние вкладки «Книги», «Сериалы», «Фильмы»; сортировка внутри категории по алфавиту.
- Основное представление — **вертикальный компактный список**, не сетка. Позднее можно добавить переключение вида; не входит в MVP.
- Карточка: мини-обложка слева; название, год и автор (для книги) справа; метка **«Есть пробный доступ»**, если применимо.
- На карточке каталога **нет** цены, количества слов/уроков и метки «Приобретено».
- По нажатию открывается подробная страница. На ней показываются описание, уровень CEFR, полные количественные показатели, структура, цена и действия по покупке/доступу.
- Глобальный поиск прямо в каталоге, по названиям на обоих языках, отдельным книгам/сезонам и авторам книг. **Не искать по названиям глав и эпизодов.** Результаты сгруппированы по типам. Поиск по локальному индексу SQLite с debounce.
- Кнопка фильтров в виде небольшого значка рядом с поиском; фильтры **«Уровень английского»** и **«С пробными уроками»** общие для трёх вкладок каталога. При активном фильтре — точка/небольшой индикатор.
- Поиск работает внутри активных фильтров. Если результатов нет и фильтры активны — «Сбросить фильтры» без очистки поиска.
- При открытии произведения и возврате запрос/фильтры сохраняются. При выходе из каталога и повторном входе — сбрасываются.
- Книжная серия и сериал отображаются одной общей карточкой. Неопубликованные тома/сезоны скрыты, без карточек «Скоро».

## 8. Экран произведения и последовательность уроков

- Для книжной серии/сериала показать вертикальный список отдельных опубликованных приобретаемых книг/сезонов, включая уже доступные и ещё платные.
- Экран конкретной книги: небольшой заголовок с обложкой и названием, который уходит при прокрутке, ниже сетка глав; без повторяющихся больших счётчиков прогресса.
- Для сезона — аналогичная сетка эпизодов. Для фильма — непосредственно сетка уроков.
- Экран главы/эпизода — название и сетка уроков, без повторной большой обложки.

### 8.1. Сетка-карта пути

- Две колонки карточек с порядком «змейкой»: первая строка слева №1, справа №2; вторая строка справа №3, слева №4 и т. д.
- Между карточками плавная непрерывная изогнутая линия, **без стрелок**. До текущего доступного шага линия выделена, дальше нейтральная/серая.
- Пройденные и текущие доступные карточки одинакового основного цвета; у пройденной дополнительно небольшая надпись **«Пройдено»**. Без обязательных галочек и зелёной рамки.
- Неоткрытые по порядку **уже доступные** уроки/главы — нейтральные, **без замка**. По нажатию краткое объяснение последовательного прохождения.
- Неоплаченные единицы помечаются **замком**; нажатие открывает предложение покупки соответствующей книги/сезона/фильма.
- Карточки уроков — компактные, почти квадратные (примерный формат ширина:высота 1,2–1,3), с номером; заголовки глав/эпизодов выводятся полностью, при необходимости строка/ряд увеличивается по высоте, без обрезания названий.
- При открытии незавершённого произведения автопрокрутка к **первой незавершённой** главе/эпизоду и затем к первому незавершённому уроку; для полностью пройденного — к началу. По завершении урока позиционировать следующий доступный урок примерно по центру.
- Когда добавлены новые уроки в старую главу, сначала предлагать самый ранний незавершённый материал; уже завершённые позже главы не надо перепроходить.

### 8.2. Поведение завершённых карточек

**Завершённый урок** переворачивается по нажатию (эффект 3D) и показывает две вертикальные кнопки с иконками: «Повторить», «Слова». «Повторить» — короткое повторение пяти заданий; «Слова» — небольшое модальное окно со словами урока, переводами и отдельными закладками.

**Завершённая глава/эпизод** переворачивается и показывает «Уроки» и «Слова». «Уроки» открывает сетку уроков. «Слова» открывает отдельную страницу всех слов главы/эпизода, сгруппированных по урокам, с тонкими разделителями.

- Только одна карточка перевёрнута одновременно.
- Закрытие модального окна или уход из действия возвращает карточку лицевой стороной.
- Пять слов завершённого **урока** можно увидеть сразу после его прохождения; полный список **всей главы** доступен только после завершения главы.
- Для списка слов главы не нужны поиск, свёрнутые секции и пакетное добавление в словарь.

## 9. Учебная единица и содержание

- Урок всегда состоит **ровно из пяти** учебных единиц: отдельных слов, фразовых глаголов, устойчивых выражений и допустимых грамматических конструкций.
- Одно слово с другим значением может стать отдельной учебной единицей; одно значение в пределах книги / сезона не повторять. Между разными книгами или сезонами совпадения разрешены.
- Исходный порядок слов соответствует порядку первого появления соответствующих значений в главе/эпизоде/фильме.
- Учебная лексика хранится в словарной/базовой форме; упражнения вправе использовать грамматические формы из контекста.
- Для подготовленных заданий использовать **собственные предложения**, а не копировать цитаты из защищённых произведений. Не создавать спойлеров.
- Тексты самих книг/полные субтитры не входят в публичные пакеты как учебные упражнения.
- Имена персонажей, названия вымышленных мест и организаций не являются учебными единицами, но обычные полезные слова в их составе допускаются.
- Сленг, грубые выражения и тематическую лексику добавлять выборочно при реальной значимости; простые разговорные сокращения вроде gonna/wanna обычно не выделять в отдельные задания.
- Общий принцип — полезность для понимания конкретного произведения, а не искусственно фиксированное количество единиц в главе. Итоговое количество кратно пяти.

## 10. Основной урок: точное поведение

### 10.1. Состав

**16 базовых заданий на пять слов**:

1. **5** × английское слово/выражение → выбор одного из **4 русских переводов**. Дистракторы правдоподобные, но однозначно неверные для заданного значения, сопоставимой грамматической роли.
2. **5** × русское предложение → выбор одного из **4 полных английских предложений**. **Все четыре английских ответа содержат изучаемое слово/выражение в нужном значении**; правильным является лишь полное предложение с нужным смыслом.
3. **5** × английское предложение → выбор одного из **4 полных русских переводов**; только один корректно передаёт смысл.
4. **1** × «Найди 5 пар»: пять английских единиц и пять русских значений в двух независимо перемешанных колонках.

- Общий порядок заданий управляемо перемешивается: первая встреча каждого слова — тип 1; не два соседних задания по одному слову; пары ближе к концу (примерно на позиции 13); последние задания предпочтительно контекстные.
- Варианты ответа случайно перемешиваются при каждом показе вопроса, включая перепрохождение незавершённого урока и задания интервальных повторений.
- Предложения/варианты могут занимать несколько строк, варианты вертикальные, ширина экрана, без горизонтальной прокрутки; при необходимости доступна вертикальная прокрутка.
- Целевой фрагмент **не выделять жирным до ответа**.

### 10.2. Ответ и обратная связь

- Одно нажатие сразу фиксирует ответ, повторный выбор невозможен до перехода.
- Верный вариант подсвечивается зелёным, выбранный неверный — красным.
- Нижняя панель: «Верно!» или «Не совсем», фиксированная кнопка «Продолжить».
- Для простого задания «слово → перевод» после ответа дополнительно показать собственный английский пример и русский перевод. Изучаемое выражение выделить **жирным в обоих языках**.
- Для контекстных заданий не дублировать выбранные предложения и не добавлять автоматическое длинное грамматическое объяснение — верный ответ уже виден в вариантах.
- Подсказок и возврата к предыдущему вопросу нет.

### 10.3. «Найди 5 пар»

- Можно выбирать сначала английское или русское значение.
- Выбор другого элемента в той же колонке меняет выделение.
- Неверная пара кратко краснеет, затем оба элемента снимают выделение; ошибка **не учитывается** при расчёте дополнительных упражнений.
- Найденная пара остаётся подсвеченной зелёным и недоступной для выбора.
- По завершении пятой пары — краткая обратная связь и **автоматический переход** без кнопки «Продолжить».
- Прогресс-бар сдвигается за задание с парами в целом, не за каждую пару.

### 10.4. Дополнительная отработка ошибок

- После 16 базовых заданий добавить **одно дополнительное упражнение на каждое слово**, в упражнениях которого была хотя бы одна ошибка (максимум пять; всего 16–21).
- Выбирать наиболее сложный из ошибочных типов, отдавая предпочтение контекстным.
- Никакого отдельного экрана «Работа над ошибками»; продолжение бесшовное.
- Прогресс-бар не откатывается и достигает 100% только после последнего фактического задания. Не показывать счётчик ошибок.

### 10.5. Прерывание

- Верхняя область урока: кнопка закрытия **X** и полоска прогресса.
- При намеренном закрытии посреди урока — подтверждение выхода.
- Если урок не завершён, при последующем входе запускать с первого задания; порядок типов стабилен по правилам урока, позиции вариантов меняются.
- Если приложение просто свернули и процесс жив, текущий экран может сохраниться; после принудительного закрытия/рестарта незавершённый урок начинается сначала.
- Сохранение статуса «урок завершён» происходит **сразу после последнего задания**, до показа итогового экрана.
- Не повторять экран поздравления после нового запуска, если урок уже был завершён.

### 10.6. Звук и вибрация

- Небольшие звуки верного/неверного ответа и тонкая тактильная отдача; отдельные выключатели, по умолчанию включены.
- Звуки учитывают беззвучный режим устройства.
- Изображения или озвучка отдельных слов в уроках первой версии не нужны.

## 11. Итоги урока и завершение глав/произведений

### 11.1. Итоги урока

- Пять английских слов/выражений в исходном порядке появления; под каждым русский перевод; один общий список со строками и тонкими разделителями, не пять отдельных карточек.
- Справа у каждого — отдельная закладка для личного словаря.
- Основные действия внизу: «Следующий урок» (сразу запускает следующий доступный) и «Вернуться к главе».
- После последнего урока главы действие меняется на «Завершить главу» с переходом к итогам главы.
- После самого последнего урока книги/сезона/фильма показывать итог **произведения** вместо лишнего промежуточного экрана.
- После последнего бесплатного пробного урока — «Завершить пробную часть» и отдельное предложение покупки.

### 11.2. Итоги главы/эпизода

- Заголовок, две крупные статистики рядом: **N слов** и **N уроков**.
- Кнопки «Продолжить обучение» (к следующей *незавершённой* главе/эпизоду) и «К списку глав» / «К списку эпизодов».

### 11.3. Итоги книги/сезона/фильма

- Название, общее количество изученных слов, количество завершённых глав/эпизодов/уроков.
- «Вернуться в библиотеку» → «Моя библиотека» / «Изучаю».
- Без очков, достижений, графиков ошибок и отдельного начисления SRS.

## 12. Короткое повторение завершённого урока

- Запускается через оборот завершённой карточки.
- **Ровно 5 вопросов**, по одному на каждое слово.
- Случайно выбирать один из двух **контекстных** типов основного урока.
- Тот же базовый интерфейс ответов и полоска прогресса, без дополнительных заданий за ошибки.
- После последнего вопроса **без отдельного экрана завершения** возврат к сетке уроков; карточка — лицевой стороной.
- Ошибки не меняют статус «Пройдено» и не являются событиями интервального повторения.
- Короткое повторение доступно офлайн при наличии скачанного пакета.

## 13. Личный словарь

- Слова **никогда не добавляются автоматически** после урока.
- Пользователь отдельно нажимает закладку на экране итогов, в модальном окне слов завершённого урока или в списке слов завершённой главы/эпизода.
- Заполнение/очистка значка сразу отражает состояние, без всплывающего уведомления при обычном действии.
- Нет пакетного добавления/удаления и нет произвольного ввода слова пользователем.
- При первом добавлении — один объясняющий диалог о повторениях с предложением включить местное ежедневное уведомление; запрашивать системное разрешение **только** если пользователь согласился. При отказе не предлагать снова автоматически; включение доступно в настройках.
- Если у слова уже есть история интервальных повторений, удаление требует подтверждения с предупреждением о сбросе прогресса. Если истории ещё нет — сразу удалить.
- Повторное добавление после удаления начинает интервальную историю заново.
- Добавление и удаление работают офлайн: локальная SQLite и очередь отправки. Перед запуском онлайн-повторений сначала отправлять ожидающие операции словаря; пока добавление слова не подтверждено сервером, повторение этого слова не запускается.

## 14. Интервальные повторения (SRS)

- **Требуется интернет**. Сервер Django рассчитывает интервалы, уровни и даты повторения; приложение не дублирует алгоритм.
- Используются упражнения с выбором из **четырёх вариантов**, без ручного ввода слов, без «сам оценил» и без озвучки в MVP. Небольшое число типов (2–3), включая контекстные.
- Очередь **до 10 слов**; при остатке **2** клиент запрашивает/добавляет до **8** новых, без экрана завершения между партиями.
- Отображать счётчик **«Осталось: N»** — число слов, доступных к повторению.
- При ошибке слово удаляется из текущей очереди, новый срок — **сейчас**, поэтому оно может появиться снова в тот же день после обновления очереди.
- Правильный ответ: интервалы по последовательности **1, 2, 4, 7, 10, 14, 21 день**, затем более длительные интервалы вплоть до ежемесячных. Для первых семи шагов сроки определены; точную дальнейшую последовательность зафиксировать при проектировании до выпуска.
- Неверный ответ: уровни **1–4 → 1**, **5–6 → 2**, **7 и выше → 3**. Дата следующего повторения — сейчас.
- Новое сохранённое слово доступно к первому повторению немедленно (`next_review_at = now()`), после первого правильного ответа — через один день.
- На карточке повторения предусмотрено удаление слова с подтверждением при наличии истории.
- При потере интернета повторение приостанавливается; уже подтверждённые сервером ответы остаются сохранёнными. Не создавать офлайн-очередь результатов SRS.
- Если нет ни одного сохранённого слова — пояснение и переход в библиотеку. Если слова сохранены, но срок не наступил, — информация о ближайшем повторении.
- У вкладки «Повторения» значок количества готовых к повторению слов, полученный от сервера при актуальном соединении; не выдавать устаревшие данные за свежие.

## 15. Гибридный офлайн-режим и синхронизация

**Действующее требование, заменяющее прежнюю модель «всё офлайн» и промежуточное решение «все уроки онлайн».**

| Действие | Без интернета | Источник истины после синхронизации |
|---|---|---|
| Просмотр ранее скачанного каталога и произведений | Да | Контентный снапшот/сервер |
| Прохождение обычного урока | Да | Сервер + локальная очередь до подтверждения |
| Переход к следующему скачанному уроку | Да | Объединённые завершения уроков |
| Короткое повторение урока | Да | Не влияет на SRS |
| Добавить/удалить слово в словаре | Да | Состояние словаря на сервере с учётом очереди |
| Интервальные повторения | Нет | Django/PostgreSQL |
| Покупка / выдача нового права | Нет | Django/PostgreSQL |
| Получение нового или изменённого пакета | Нет | Версионированный контент |
| Первоначальный вход в аккаунт | Нет | Django/внешний провайдер |

### 15.1. События обычного обучения

- При последнем ответе урока клиент **сначала надёжно сохраняет завершение в SQLite**, затем показывает итог.
- Создаётся операция синхронизации с устойчивым идентификатором (например, UUID), привязанная к аккаунту, произведению, уроку и версии учебного контента.
- Автоматическая отправка при подключении; успешный ответ сервера фиксируется локально. Повторная отправка **идемпотентна**, не создаёт двойной прогресс.
- Объединение завершённых уроков разных устройств: логика монотонная — если урок завершён хотя бы на одном устройстве, общий статус «завершён».
- Следующая доступность уроков в офлайне рассчитывается по локально подтверждённым/ожидающим отправки завершениям и скачанным зависимостям.
- При несовместимости версии контента прогресс не стирать; сервер должен корректно сопоставлять стабильные ID.

### 15.2. Операции личного словаря

- Сохранять офлайн-действия добавления/удаления с отдельными ID операций и порядком внутри одного устройства.
- Сервер подтверждает операции и возвращает актуальное состояние; при несовпадающих действиях двух устройств нужен **детерминированный алгоритм конфликта**, который агент должен предложить до разработки.
- Нельзя слепо перезаписать целый словарь последним синхронизированным снимком, уничтожив независимые изменения другого устройства.
- Операции удаления слов с историей SRS должны учитывать подтверждение пользователя и сброс прогресса на сервере.

### 15.3. Моменты синхронизации

- Автоматически после восстановления сети, при запуске приложения и после значимых изменений. При возвращении из фона проверять обновления каталога, если с последней проверки прошёл **более 1 часа**; при необходимости — периодическая синхронизация с разумным ограничением частоты запросов.
- В настройках: время последней **успешной** синхронизации и кнопка «Синхронизировать сейчас».
- Не показывать постоянный статус подключения во всех экранах. Существенные проблемы длительной синхронизации должны быть доступны пользователю; точный порог уведомления согласовать при разработке.
- При ошибке синхронизации локальная очередь не удаляется, повтор производится безопасно, с ограничением частоты попыток.
- Локальные данные и очередь изолированы по аккаунту.

### 15.4. Обновление учебных пакетов

- Каталог, обложки и пробные пакеты доступны в локальном кэше; приобретённые полные пакеты автоматически скачиваются целиком.
- Каждый публичный пакет версионирован; сначала скачать и проверить новый пакет, потом атомарно переключить активную версию. Старую версию держать до завершения замены.
- Не подменять содержимое текущего урока посреди прохождения: изменения вступают в силу после выхода или завершения урока.
- Стабильные ID слов/уроков и корректное сопоставление прогресса обязательны. Публикация дополнительных уроков не сбрасывает ранее завершённые главы.
- При повреждённом файле/обрыве загрузки оставлять прежнюю рабочую версию.
- Полноценный пользовательский менеджер скачиваний и удаление пакетов в MVP не нужны.

## 16. Права доступа и коммерческие состояния

### 16.1. Пробная часть

- Автор вручную включает/отключает пробную часть у конкретного произведения; она есть **не у всех**.
- Книга — **первая глава**.
- Сериал — **первый эпизод первого сезона** (не гарантировать пробный доступ для других сезонов).
- Фильм — **первые три урока**.
- Пробные материалы доступны из каталога, **не добавляют произведение в «Мою библиотеку»**.
- После последнего бесплатного урока — экран завершения пробной части с одним предложением покупки и объёмом/ценой **всего** произведения, а не оставшихся после пробы уроков.
- При покупке сохранённый прогресс пробной части остаётся.

### 16.2. Покупки

- Продаваемая единица: книга, сезон сериала, фильм.
- На карточке общего каталога цена не показывается; на странице единицы и в диалоге покупки — цена, объём слов/уроков, число глав/эпизодов по типу.
- Корзины, промокодов и пользовательской страницы истории платежей нет.
- Сервер фиксирует платежи и права доступа (entitlements); клиент не может сам выдать себе право после возвращения с платёжной страницы.
- После входа на другом устройстве **покупки восстанавливаются автоматически**.

### 16.3. Полностью бесплатное произведение

- В Django Admin можно сделать единицу полностью бесплатной.
- Пользователь вручную нажимает **«Добавить в библиотеку»**.
- В этот момент ему выдаётся **постоянное персональное право доступа**. Если материал позднее снова становится платным, это право сохраняется.
- Возможность полностью снять с публикации допускается только в исключительных случаях (например, юридические ограничения); вопросы компенсации покупателям решаются по обстоятельствам и правилам магазина.

## 17. Оплата и магазины приложений

- Первоначальный магазин Android — **RuStore**. Google Play и iOS — возможные последующие площадки.
- Основной предполагаемый способ оплаты — **ЮKassa**. До релиза подтвердить допустимость конкретного способа оплаты цифрового контента и все требования RuStore/ЮKassa для выбранной схемы распространения.
- Django создаёт заказ и платёж; платёжный провайдер обрабатывает оплату; Django надёжно проверяет результат (серверное уведомление и/или проверка API).
- Идемпотентно выдавать право доступа только после проверенного успешного статуса.
- При возврате пользователя из платёжного сценария автоматически проверять статус через сервер: подтверждено / в обработке / не прошло. Не заставлять вручную нажимать «Проверить оплату».
- Защитить от повторной оплаты одного незавершённого заказа, повторных webhook-событий и двойной выдачи прав.
- Точные реквизиты, юридическая форма, чеки и возвраты — отдельные вопросы коммерческого запуска; **не считать реализованными без проверки**.

## 18. Django Admin, импорт, публикация

### 18.1. Управление каталогом

Администратор создаёт и редактирует книжные серии, книги, главы, сериалы, сезоны, эпизоды, фильмы, уроки, обложки, цены, пробный/бесплатный режим и порядок показа.

- Произведения являются **черновиками** до ручного действия «Опубликовать».
- В каталоге видны только опубликованные и доступные единицы.
- Черновые материалы разрешено тестировать в dev-режиме мобильного приложения.

### 18.2. Импорт контента

- Генерация слов/упражнений с помощью ИИ — внешний редакционный процесс. Его промпты и разбиение текстов книг **не входят в функциональность приложения**.
- Исходные JSON-файлы остаются основным редактируемым источником учебных упражнений.
- Импорт через Django Admin: выбирается конкретная глава/эпизод, загружается **один полный JSON на главу/эпизод**, содержащий все уроки этой единицы. Для фильма — соответствующий полный набор уроков в согласованном формате.
- Перед записью выполнить схематическую/структурную проверку: обязательные поля, типы, ровно пять слов на урок, количество и типы заданий, четыре варианта там, где положено, корректность ссылок, диапазон номеров, стабильные ID, дубли, ожидаемые переводы и порядок.
- Содержательную безошибочность переводов валидатор гарантировать не может. В случае формальных ошибок **не проводить частичный импорт**, показывать локализованный отчёт об ошибках по пути JSON/уроку/заданию.
- Повторный импорт обновляет данные без бессмысленной смены идентификаторов и потери прогресса.

### 18.3. Редактирование и версии

- Исправления делать в исходном JSON и повторно импортировать, **не обязательно строить UI редактирования каждого упражнения в Django Admin**.
- Повторный импорт опубликованного материала сначала изменяет **черновую версию**. Действующая публичная версия не меняется.
- После проверки автор отдельно нажимает «Опубликовать обновление»; опубликованный версионированный пакет обновляется.
- История произвольного отката прошлых редакций в админке **не входит в MVP**. При ошибке автор снова исправляет JSON и публикует новую версию.
- Нужно всё равно хранить действующий опубликованный снимок до успешной замены — это требование технической надёжности, не «история откатов».

### 18.4. Dev-тестирование

- В сборке для разработки есть простой доступ к неопубликованным материалам.
- Тестовый прогресс и закладки изолированы от обычного пользовательского обучения; можно сбросить тестовый прогресс и повторить урок.
- Функции тестового режима **отсутствуют в публичной сборке**, не раскрывают черновики обычным пользователям.
- Без сложной системы тестовых организаций/ролей сверх необходимых прав администратора.

## 19. Уведомления

### 19.1. Интервальные повторения

- Локальное системное напоминание максимум один раз в день, по умолчанию предлагаем **19:00**, с возможностью сменить время или отключить.
- Первый запрос — после первого ручного добавления слова; объяснение, затем системное разрешение только при согласии.
- Повторно автоматически не навязывать при отказе.

### 19.2. Новые учебные материалы внутри приложения

- Значок колокольчика в правом верхнем углу «Моей библиотеки», счётчик непрочитанных.
- Уведомлять только о новых книгах **той серии, в которой пользователь уже приобрёл книгу**, новых сезонах **сериала, от которого он приобрёл сезон**, и новых уроках **в приобретённых единицах**. Не уведомлять о всех новинках каталога.
- Уведомлять только о публикациях, вышедших **после** соответствующего приобретения/получения права.
- Несколько новых книг одной серии допустимо объединять в одно уведомление с перечнем новых объектов.
- При открытии списка уведомления становятся прочитанными; история хранится. По нажатию открыть целевой раздел, при необходимости прокрутить к новому элементу и кратковременно показать метку «Новое».

## 20. Жалобы на задания и отчёты

- В упражнениях — действие «Сообщить об ошибке» с коротким комментарием и автоматическими ID произведения, версии, урока и задания.
- Офлайн-жалобы сохраняются в SQLite и отправляются при восстановлении подключения. Пользователь видит корректное состояние «сохранено для отправки»/«отправлено».
- Django Admin показывает список жалоб с контекстом задания; отдельная сложная тикет-система не требуется.
- Для коммерческого использования предусмотреть автоматические отчёты о сбоях с минимумом данных, без полнотекстовых книг и личной истории слов.
- Базовая аналитика событий: открытия материалов, начало/завершение уроков, использование пробных частей, переходы к покупке. В настройках переключатель **«Анонимная аналитика»**, по умолчанию включён по продуктовой задумке, но режим согласия/законность для целевых юрисдикций проверить перед выпуском. Система crash reporting настраивается отдельно.

- Названия/описания произведений локализованы; **упражнения всегда английский ↔ русский** независимо от локали UI.
- Тема: светлая, тёмная, системная; по умолчанию системная.
- Отдельно включаются/выключаются звук и вибрация.
- Время и статус уведомлений о повторениях.
- Анонимная аналитика; crash reporting отдельно.
- Информация об аккаунте, связанные способы входа, выход, удаление.
- Последняя успешная синхронизация и ручной запуск.
- Дополнительную страницу «Моя статистика», достижения, аватары и социальные функции не делать.

## 22. Концептуальная модель данных (для проектирования, НЕ окончательная схема БД)

Агент должен предложить нормализованные Django-модели с миграциями и явными связями. Ожидаемые предметные сущности:

- **User**, **ExternalIdentity** (провайдер + проверенный внешний идентификатор).
- **BookSeries**, **Book**, **Chapter**.
- **Show**, **Season**, **Episode**.
- **Movie**.
- **Lesson**, **LearningItem** (конкретное слово/выражение + нужное значение в контексте), **Exercise**, **AnswerOption** либо эквивалент в версионированных пакетах.
- **ContentDraft/PublishedRevision**, **Asset/PackManifest** (или другие механизмы управляемой публикации).
- **Entitlement**, **Order/Payment**.
- **LessonCompletion** (с уникальностью для аккаунта и урока), **SyncEvent/Inbox** для идемпотентности, при необходимости **Device/SyncCursor**.
- **Bookmark** / личный словарь, **SRSState** и события ответов SRS.
- **ErrorReport**, **InAppNotification**.

**Нельзя без анализа автоматически создавать отдельную SQL-таблицу на каждую JSON-сущность.** Агент должен обосновать, какие данные требуется хранить реляционно ради редактирования и запросов, а какие эффективнее хранить в структурированных опубликованных JSON-пакетах. При этом стабильные ID и обработка жалоб по ID обязательны.

## 23. Требования к API (логические операции; URL не утверждены)

Агент должен предложить контракты и схемы валидации, включая минимум:

1. Получить/обновить пользовательскую сессию через Google/Яндекс ID.
2. Получить сведения о текущем аккаунте и привязанных провайдерах.
3. Получить каталог/манифест версий/права доступа и защищённые ссылки на допустимые пакеты.
4. Получить подтверждённый прогресс пользователя и синхронизационный курсор.
5. Пакетно отправить локальные **завершения уроков** с идемпотентными ID событий; получить подтверждение и нормализованное состояние.
6. Пакетно отправить **операции личного словаря**; получить подтверждение/конфликты и итоговое состояние.
7. Получить число и очередь доступных SRS-повторений.
8. Отправить результат одного SRS-задания идемпотентно и получить серверное обновление уровня/срока.
9. Получить состояние заказа, создать платёж, проверить entitlement.
10. Получить/отправить жалобы на задания.
11. Получить/отметить прочитанными уведомления внутри приложения.
12. Изменить настройки аккаунта, удалить аккаунт.

Все приватные операции требуют валидной авторизации; платёжные уведомления — проверки подлинности по правилам провайдера. Требования к пагинации, версиям API, таймаутам и повторным попыткам задать в архитектуре, но без избыточного усложнения.

## 24. Нефункциональные требования

### 24.1. Надёжность

- Не терять завершение обычного урока после последнего задания, даже если нет сети или приложение закрылось до синхронизации.
- Повторная доставка одного события не изменяет прогресс дважды.
- Приём новой версии контента атомарный: при сбое старая версия доступна.
- Изменение/удаление слов не приводит к дублированию SRS-состояния и случайному запуску повторений без подтверждения сервера.
- Разные аккаунты на одном устройстве не видят персональные данные друг друга.

### 24.2. Безопасность

- Не хранить на клиенте секреты платёжного провайдера, ключи подписи и серверные админ-токены.
- Проверять права доступа на сервере для каждой выдачи платного пакета.
- Использовать защищённые каналы, безопасное хранение учётных токенов, минимально необходимые данные.
- Ограничить административный и тестовый доступ. Отчёты об ошибках не должны включать полный текст книг или токены.
- Резервное копирование PostgreSQL и исходных JSON обязательно как эксплуатационная задача.
- Юридические вопросы авторских прав, условий магазина, персональных данных и платёжного провайдера проверять до публичного выпуска.

### 24.3. UX и производительность

- Основные экраны и скачанные упражнения открываются из локального кэша без запроса контента при каждой навигации.
- Длинные варианты ответов полностью читаемы на небольшом экране; не обрезать названия глав.
- Ошибки сети не показывать как потерю учебного прогресса, если он уже сохранён локально.
- Отсутствие скачанного платного пакета объяснять понятным состоянием, с автоматической повторной загрузкой при появлении сети.
- Не добавлять сторонние анимации/эффекты, которые ухудшают скорость и доступность интерфейса.

## 25. Проверочные сценарии (минимальные критерии приёмки)

1. **Первый запуск:** новый пользователь проходит Google/Яндекс ID, видит подготовку каталога и оказывается в пустой «Моей библиотеке».
2. **Пробный урок:** в каталоге открывается назначенная пробная глава/эпизод/часть фильма без попадания в библиотеку; после завершения показывается предложение купить целую единицу.
3. **Базовый урок:** ровно 5 слов, 16 основных заданий; каждая ошибка слова добавляет максимум одно дополнительное упражнение; на итогах 5 отдельных закладок.
4. **Выход из урока:** закрытие на 12-м вопросе после подтверждения, повторный вход начинает с первого; завершение после последнего вопроса сохраняется немедленно.
5. **Офлайн-прогресс:** скачанный урок полностью проходится без интернета; после перезапуска результат «Пройдено» не теряется; после восстановления связи сервер принимает событие ровно один раз, даже при повторной отправке.
6. **Два устройства:** уроки, завершённые на разных устройствах, после синхронизации оба остаются завершёнными.
7. **Офлайн-словарь:** добавить и удалить слова без сети; после синхронизации сервер и клиент согласованы; конфликт параллельных действий имеет предсказуемый результат.
8. **SRS:** в режиме офлайн не запускается; онлайн выдаётся очередь до 10 заданий; ответ меняет срок на сервере; сбой на 8-й карточке не теряет первые 7 подтверждённых ответов.
9. **Повторение урока:** пять контекстных заданий не меняют завершённость урока и SRS.
10. **Контентная публикация:** черновик не виден публично; после ручной публикации появляется в каталоге; правка опубликованной главы остаётся черновиком до отдельного подтверждения.
11. **Обновление пакета:** новый JSON скачивается и применятся атомарно после урока; прогресс старых стабильных ID остаётся; добавленные уроки делают прежде завершённую главу незавершённой без повторного прохождения других.
12. **Покупка:** нельзя получить право доступа только по успешному возврату из платёжной формы; после серверного подтверждения entitlement возникает один раз; на другом устройстве покупка восстанавливается автоматически.
13. **Бесплатная раздача:** материал бесплатно добавлен в библиотеку; после возврата платной цены доступ у этого пользователя остаётся.
14. **Изоляция аккаунтов:** после выхода и входа другого аккаунта персональный прогресс и чужие купленные материалы недоступны.
15. **Жалоба без сети:** сообщение сохранилось на устройстве и попало в Django Admin после восстановления связи.
16. **Dev-режим:** неопубликованный материал доступен для теста с отдельным сбрасываемым прогрессом, но отсутствует в публичной сборке.
17. **Каталог:** вертикальный список, поиск по отдельным книгам внутри серии, фильтры сбрасываются лишь при повторном входе в каталог, а не после возвращения с карточки.
18. **Локализация:** UI переключается ru/en, обложка не меняется, контекстные учебные задания остаются EN↔RU.

## 26. Исключения из первой версии

- Полный офлайн-SRS или полноценное распределённое разрешение конфликтов ответов SRS.

- Отдельный «главный» экран, обязательный экран онбординга.
- Встроенный ридер книг, видеоплеер, озвучка заданий, картинки в каждом задании.
- Переключение представления каталога список/сетка.
- Сложная система тикетов, редактор отдельных упражнений в Django Admin, история откатов версий.
- Автоматическая генерация обложек сервером.
- Автоматическое добавление всех слов урока в словарь и ввод произвольных слов.
- Удаление уже скачанных учебных пакетов из приложения.

## 27. Неутверждённые вопросы / технические решения для архитектурного этапа

**Агент должен оформить предложения, но не выдавать их за ранее утверждённые требования:**

1. **Формальная JSON-схема** для главы/эпизода/фильма, локализации, идентичности учебных единиц и версионирования. Совместимость при повторном импорте.
2. **Хранение модели упражнений**: реляционные данные против опубликованных JSON, и граница между Django Admin и Object Storage.
3. **Разрешение конфликтов закладок** при противоположных офлайн-действиях с двух устройств; порядок операций, ревизии, удаление SRS-истории.
4. **Надёжный протокол синхронизации**: идемпотентность, курсоры, подтверждение очереди, повторные отправки, привязка к версии контента.
5. **Защищённая доставка платных пакетов**, кэширование на устройстве и отзыв доступа в юридических исключениях.
6. **Точная схема оплаты ЮKassa с RuStore**, статус заказа, поддержка возвратов, совместимость с правилами площадки.
7. **Интервалы SRS после 21 дня** и конкретный алгоритм выбора типов заданий для очереди.
8. **Ручной экспорт/импорт полного прогресса**: ранее рассматривался как основной перенос между устройствами, но после внедрения облачной синхронизации потерял первоочередную необходимость; считать отложенной функцией, пока отдельно не подтверждена.
9. **Порог предупреждения о проблемной синхронизации**, мониторинг, резервные копии и инструмент тестирования конфликта двух устройств.
10. **Правовая проверка** условий RuStore/ЮKassa, лицензий на изображения и обработки данных перед релизом.

Работать последовательно, каждый этап должен давать проверяемый результат. Не создавать весь функционал разом.

| Этап | Результат | Проверка |
|---|---|---|
| 0. Архитектурный проект | ER-диаграмма, каталог сущностей, схема JSON, модель версионирования, контракты API и синхронизации, ключевые риски | Разработчик утверждает до кода |
| 1. Контентный backend | Django/DRF/PostgreSQL, Django Admin, импорт одной реальной главы, черновик/публикация | Глава загружается одним JSON, валидируется, публикуется отдельным действием |

| 3. Обучение офлайн | Все 16 типов/экранов, дополнительные задания, итоги, короткое повторение, локальные завершения, словарь | Урок можно закончить в авиарежиме, результат остаётся после рестарта |
| 4. Аккаунты и sync | Google/Яндекс ID, серверный прогресс, права доступа, надёжная очередь завершений и закладок | Два устройства; идемпотентность; конфликты закладок проверены |

> **Важно для этапов 1–3.** Для раннего локального тестирования разрешены только dev-заглушки авторизации/прав. В публичной сборке обязательна реальная авторизация с первого запуска; не допускать превращения временных тестовых обходов в пользовательскую функцию.

## 29. Указания ИИ-агенту

1. **Сначала изучить ТЗ полностью**, перечислить найденные противоречия и нерешённые архитектурные вопросы. Приоритет — последние зафиксированные решения.
2. **Не писать весь проект в одном проходе.** Сначала предложить архитектуру, схему данных, версионирование JSON и механизм sync; разработчик утверждает.
3. Не расширять MVP «полезными» возможностями без отдельного согласования.
4. Не предлагать микросервисную архитектуру и тяжёлую инфраструктуру без практического обоснования для одного разработчика.
5. На каждом этапе: план → реализация → миграции/тесты → самопроверка по критериям → краткий отчёт о сделанном и известных ограничениях.
6. Все изменения кода в отдельном логическом наборе с понятными именами, тестами и инструкциями запуска. Работать так, чтобы владелец мог понять и поддерживать проект.
7. Если обнаружена неоднозначность, указывать **конкретные варианты и их последствия**. Не подменять продуктовые решения своими предпочтениями.
8. Предпочитать первоначальный рабочий вертикальный сценарий: **реальная глава → JSON → Django Admin → опубликованный пакет → React Native/SQLite → 16 заданий → завершение → серверная синхронизация**.
