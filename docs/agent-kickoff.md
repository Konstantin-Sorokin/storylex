# Стартовое задание ИИ-агенту: архитектурное проектирование

Прочитай целиком файл `requirements.md`. Это единый источник требований к мобильному приложению изучения английского по книгам, сериалам и фильмам.

**Текущая задача — только архитектурное проектирование. Пока не создавай приложение и не начинай масштабные правки репозитория.**

Подготовь на русском:

1. Краткую карту системы: Expo/React Native + SQLite; Django/DRF + PostgreSQL; доставка версионированных JSON-пакетов и обложек; внешняя авторизация; платёжная система в будущем.
2. Предлагаемую организацию монорепозитория или отдельных репозиториев с обоснованием для одного разработчика. Не навязывай микросервисы.
3. Список Django-приложений/моделей, ключевые связи и ограничения БД. Укажи, какие данные хранить реляционно, а какие в опубликованных JSON.
4. Версионированную JSON-схему главы (5 слов/урок, 16 стандартных заданий), правила импорта целой главы, повторного импорта и сохранения стабильных ID/прогресса. Аналогии с эпизодом и фильмом.
5. Контракты API: авторизация, манифест и права, скачивание контента, синхронизация завершений уроков и изменений личного словаря, серверные интервальные повторения, платежи, жалобы.
6. Простую, но надёжную схему синхронизации: обычные уроки офлайн, запись события завершения в SQLite, очередь идемпотентной отправки, объединение завершений с разных устройств; для закладок — предложи ясный способ разрешения конфликтов; SRS только онлайн.
7. Модель атомарного обновления скачанных учебных пакетов без потери прогресса и незавершённого урока.
8. Безопасную схему выдачи платного JSON по серверному entitlement. Не считать Object Storage приватным, если файлы доступны по публичной ссылке.
9. Разделение на этапы разработки с **первым минимальным вертикальным сценарием**: импорт реальной главы → публикация → клиент загружает пакет → пользователь проходит урок → локальное завершение → серверное подтверждение.
10. Не более 10 действительно блокирующих решений, которые должен принять владелец проекта до написания кода; всё остальное изложи как разумные технические предложения и пометь их как предложения.

**Ограничения:** Python/Django/DRF/PostgreSQL для сервера; React Native/Expo/TypeScript/SQLite для клиента; Android и RuStore первыми; Google + Яндекс ID; ЮKassa как предполагаемый провайдер оплаты; пользователь разрабатывает проект в одиночку. Никакой функциональности вне ТЗ без предварительного одобрения.

**Формат ответа:** архитектура → модель данных → схема JSON → API → синхронизация → безопасность/риски → этапы → вопросы к владельцу. Важные компромиссы поясняй, не ограничивайся названием технологий.
